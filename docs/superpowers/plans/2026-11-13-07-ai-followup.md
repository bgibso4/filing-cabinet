# AI Follow-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Suggestions that arrive on Ben's phone and read like titles he'd type, judged by Ben, plus TelemetryDeck sending from Release builds.

**Architecture:** Analytics gets a pure event→signal mapping and a sink choice in `Core` (tested in Fast) and a thin TelemetryDeck sink in the app. The card's wait goes to 10 s. The eval learns a strict title check, a private case set outside the repo, a local review page and a merge of Ben's answers; the suggester learns a second title style (name + kind, composed in code), and Ben's side-by-side ticks pick the style that ships.

**Tech Stack:** Swift 6, SwiftUI, FoundationModels (on-device), Swift Testing, XcodeGen, TelemetryDeck Swift SDK.

**Spec:** `docs/superpowers/specs/2026-11-13-ai-followup-design.md` (Ben's page: https://claude.ai/artifact/28b1XF7A7v6sRHbgzyW7vW).

## Global Constraints

- Branch `ai-followup` from main at 3529d73 (Plan 6 merged), in the main checkout. Every green merge to main uploads a TestFlight build.
- AGENTS.md hard rules: `package` access between modules, `public` only for app/tests; no `#available`; `os.Logger`, never `print`; `try?` only with a comment; one primary type per file; third-party packages pinned `exact:`; root `Package.resolved` is the source of truth (`make check-resolved`).
- **No real scan, its text, its image, its id or report lines in git, PRs, issues, artifacts or any service.** Private material lives only in `~/FilingCabinetPrivate/eval/` and local files.
- Evals: iterate with `CASES=` on a subset; one full `make eval-suggestions` per variant per round. Never a full run per tweak.
- Run policy: `make retest ONLY=…` while fixing, `make affected` at each task's end, `make full ALL=1` once before the PR. Build/test evidence via `ios-verifier`.
- `ScanSuggestion.promptVersion` stays 1 (it versions search words; the words prompt is untouched).
- On-device model only; E2 (image in), E3 (prewarm), E4 (split read) and Title Case stay.
- Only Release builds send to TelemetryDeck; an empty app ID sends nothing. No opt-out.
- Never record a decision as Ben's unless he made it (spec's "Decided" table).

## Review Focus

1. **A model `name` that already ends with the kind** ("City Pharmacy Receipt" + "Receipt") must give "City Pharmacy Receipt", not "…Receipt Receipt". Test in Task 6.
2. **An empty or whitespace `kind`** with a name must still give a usable title (the name), and both empty must give nil, so the card falls back to the text-rule title. Test in Task 6.
3. **A relaunch or Try again must not re-initialise TelemetryDeck or make a second sink**; one sink per process. Test (sink choice is pure) in Task 1; wiring checked in Task 2 by construction (`AppStartup` owns it).
4. **A private case with no expected titles yet** (before Ben's first review) must be reported as "unjudged", never counted as a miss or a hit. Test in Task 4.
5. **The first `active` after launch must not send `appOpened` twice** when both the launch path and `scenePhase` fire. Test in Task 2.
